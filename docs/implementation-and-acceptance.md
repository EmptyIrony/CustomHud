# 实现范围、阶段和验收

本文件定义新应用的开发目标。具体平台能力仍需现场确认，接口形状见其他文档。

## 1. 目标与技术边界

创建独立 Android HUD 应用。建议 Kotlin、原生 View/Canvas 和可替换的数据适配层；主屏设置页可使用团队熟悉的 Android UI 技术。应用工程应能在新的开发环境中构建，不依赖某台电脑的目录、工具安装或现有工程。

最小项目模块边界：

| 模块 | 职责 |
|---|---|
| app/settings | 入口、预览、目标屏选择、权限说明、启动/停止、可见日志 |
| display-session | Context/WindowManager、状态机、generation、监听和清理 |
| renderer | Canvas 组件、字体资源、不可变帧状态、重绘合并 |
| layout-store | schema、布局/样式/预设、原子持久化与版本迁移 |
| data-domain | 带单位、有效性、采样时间的数据模型 |
| adapters | vehicle/media/location/road 的 mock 与现场实现 |

模块可以是包或独立 Gradle module，不要求为简单功能拆分过度。包内方法名称属于接口约定，开发者需要实现它们。

## 2. 第一阶段：离线可运行版本

必须先完成：

1. 正常启动的主屏应用与 PREVIEW 模式。
2. 固定时钟、状态占位、媒体占位和可配置位置的 Canvas 渲染；模拟数据明确标识。
3. 读取/导出版本化布局文件，完整校验后原子替换；错误保留上一份有效配置。
4. 目标屏与能力列表、启动/停止和真实阶段状态，窗口操作可替换为 mock。
5. 可见日志页和用户主动导出诊断文件，包含错误码与 session generation。
6. 无车辆 SDK 的环境也能构建：厂商 API 在适配层按能力发现，不直接阻断普通预览。

第一阶段不要求完成拖拽编辑器、道路数据库下载、自动驾驶模式预设切换或全部装饰样式。布局文件和主屏预览足以开展显示与生命周期开发。

## 3. 第二阶段：DEVICE 显示能力

完成平台能力检查、明确目标屏选择、Context/窗口创建、View attach/draw 状态、目标移除与恢复、权限撤销、重建与停止收尾。用户现场操作前，应提供准确的构建物、运行入口和可见日志说明。

开发助手不能自动连接车辆、安装 APK、启动现场会话或改变现场配置。现场执行由用户确认后手动完成。离线构建成功与实车兼容性分别记录。

## 4. 第三阶段：只读数据

逐项接入车辆、媒体和可选位置数据。每个字段记录 profile、原始单位、归一化单位、成功采样时刻和有效性。某个数据源失败不得让其他独立组件全部停止，也不得伪造零值或新鲜时间戳。

候选属性的值、枚举、倍率和实际权限逐项验收；未完成的适配项保持 disabled/unavailable。道路提醒数据库、导航路线输入、图片资源与远程内容各自需要独立来源和格式契约。

## 5. 用户流程

首次进入显示 PREVIEW，明确模拟数据标签。用户进入 DEVICE 时，先看目标屏描述与能力状态，选择目标后再明确启动。主屏始终提供停止入口；日志可见，失败原因能直接定位到权限、目标、窗口、布局或数据源。

编辑操作默认在主屏预览页完成。HUD 上不显示开发过程、内部编号或异常堆栈；这些信息只放日志页。没有真实数据时使用配置好的占位/隐藏策略，不在现场自动切入演示值。

## 6. 有意义的离线验证

至少覆盖下列行为，而不是为每个 getter 创建测试：

| 场景 | 必须观察到的结果 |
|---|---|
| 启动成功 | 一个窗口、一组监听/任务，阶段状态与日志一致 |
| 重复 start | 不重复 addView、轮询或订阅 |
| addView 拒绝 | 失败原因可见，资源回滚，不报告已附着 |
| 等待屏幕中 stop | 取消等待；稍后屏幕出现不启动 |
| 目标移除后恢复 | 旧会话失效，新 generation 重建，仅选定目标恢复 |
| 旧媒体/车辆回调晚到 | 旧 generation 结果被丢弃 |
| stop 后回调/动画 | 不再更新现场窗口，资源计数回到零 |
| 读属性失败 | 字段变为不可用/过期，不从错误生成真实零 |
| 新旧采样乱序 | 较旧值不覆盖较新值 |
| 不合法/重复类型布局 | 整份拒绝，保留当前有效布局 |
| 切换布局/预设 | 原子提交，有明确 revision，失败不部分覆盖 |
| 权限撤销 | 对应能力降级，停止或保持其他独立能力按契约执行 |

几何验证至少覆盖两种宽高比、0/1 边界坐标、缩放范围、sp 展开关系和空 View 尺寸。对模拟渲染可保存截图供人工检查，但不能把截图测试当作 HUD 实车验证。

## 7. 现场验收矩阵

由用户手动验证并记录：

- Android/车机版本、实际应用身份和所获权限。
- 目标屏的描述、窗口添加结果、View attach 与实际显示观察。
- 原厂内容的合成效果及自定义元素可读性。
- 用户停止、主屏 Activity 离开、息屏/唤醒、目标重建、进程重启。
- 断开车辆数据、媒体会话切换、定位不可用和权限变化。
- 每项实际接入的数据单位、时间戳、未知/过期处理。

未执行的项目标记为未执行；不以同品牌另一应用的运行结果代替本应用验收。

## 8. 交付

交付新工程、Gradle Wrapper、固定依赖版本、构建说明、必要测试结果、调试 APK 及其 SHA-256、配置示例和诊断说明。开发助手应实际执行环境允许的离线构建与验证，说明剩余缺失依赖或检查；不要仅给出设计文档便结束开发任务。

现场专有 SDK 若不可取得，交付 mock、能力发现和清晰的适配接口；不虚构可下载地址或未确认的方法。后续加入真实 SDK 不应需要重写渲染与状态机。
