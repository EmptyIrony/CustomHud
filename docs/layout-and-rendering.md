# HUD 布局、预设与渲染契约

状态：非官方技术草案；实车未验证。本文是项目约定，需要实现，不表示平台内建组件已可调用。

## 1. 范围与能力分层

初版以离线固定文字、时钟及基础状态显示为目标。编辑器、自由素材制作和复杂导航后续可选。
Android Canvas／View 是公共绘制机制；目标显示面和窗口权限由单独的平台适配层提供。
本契约不定义车端控制接口，不通过布局配置执行脚本、反射类名或车辆属性写入。

## 2. 文档 envelope：项目约定，需要实现

```json
{
  "schemaVersion": 1,
  "widgets": [
    {"t":"CLOCK","en":true,"cx":0.84,"cy":0.50,"sc":0.30,"sp":0.0}
  ]
}
```

这表示一份完整布局：只包含列出的组件，未列出的类型不显示。
顶层必须是包含 `schemaVersion` 与 `widgets` 的对象；未知版本拒绝加载，保持当前有效布局。
完整组件项必须写全六个字段；同一完整文档出现重复类型时拒绝，不采用最后一项覆盖。

| 字段 | 类型 | 完整加载约束 | 单位／含义 |
|---|---|---|---|
| `t` | string | 已注册组件类型；不可为空 | 按类型单实例，不是 Java 类名 |
| `en` | boolean | 必需 | 普通启用状态 |
| `cx` | number | 有限数，0…1 | 中心锚点横向比例 |
| `cy` | number | 有限数，0…1 | 中心锚点纵向比例 |
| `sc` | number | 有限数，0.2…4 | 相对基础高度的缩放倍数 |
| `sp` | number | 有限数，0…0.5 | 成对元素水平展开比例 |

外部完整文件采用严格校验：越界、非有限数、未知类型、字段类型错误或未知结构不能静默修复。
交互编辑的内部 setter 可按表中范围 clamp；保存前仍做完整验证，不能把 clamp 当作所有输入校验。
未知字段的处理由 schema 明确约束，不允许其隐式成为扩展执行入口。

## 3. 完整替换与增量更新必须分开

`replace(LayoutDocument)` 先解析和验证整个文档，再一次性发布新的不可变布局；失败时旧布局不变。
完整替换不会把默认组件自动加回来，也不与当前布局逐项混合。
`applyPatch(WidgetPatch[])` 是另一项项目 API：每项 `t` 必需，其他字段可选，只修改已存在的类型。
增量更新遇到不存在类型、重复类型或任何非法字段时整批拒绝；新增／移除由完整替换完成。
增量更新也先构造并验证新快照，再原子发布，不边解析边改变可见画面。
兼容顶层数组仅作为显式导入模式；调用者必须指定 replace 或 patch，不按形状自动猜测并混用语义。
持久化采用临时文档校验后提交，保存失败不得使当前内存布局变成半份配置。

## 4. 单实例与项目扩展

第一版按 `t` 唯一，每种类型最多一项；重复 CLOCK 不能表达两个独立时钟。
将来需要多实例时另升 schemaVersion，引入显式实例 ID，不在当前格式中偷换 `t` 的含义。
新增组件类型（`LYRIC`、`REAR_CAMERA`）在 schemaVersion 1 内是纯增量：六字段不变，所有旧文档仍合法并原样读取，
未列出的新类型不会被补进旧布局；含新类型的文档在旧版本中会被整份拒绝并保留旧布局。
`REAR_CAMERA`（后视）的 `cx/cy/sc` 相对于显示相机的屏幕（默认屏幕 1 = 仪表），16:9，高度 = `sc` × 屏高（编辑器上限 1.0），
整体夹在屏幕内；显示模式（常显 / 非 P 挡 / 仅 R 挡 / 关）与所在屏幕属于相机设置，另存 `rear-camera` 偏好，不进入布局文档。
TEXT、IMAGE、VIDEO、NAVIGATION 等属于项目扩展，需要另外定义数据源与配置 schema。
schemaVersion 1 的 22 项目录不含这些扩展；初版固定文字可先作为离线验证画面，不依赖 TEXT 配置项。
配置化扩展需要新的明确版本；不把文字、URI 或脚本塞进六字段的数值项，也不宣称平台内建此能力。

## 6. 单位与布局公式

设实际绘制 View 的逻辑宽高为 `W,H`：

```text
anchorX = cx × W
anchorY = cy × H
baseUnit = 0.16 × H × sc
pairSpreadPx = sp × W
```

`baseUnit` 仍需由各组件转换成字号、图标及路径尺寸，不是最终文字 px 值。
`sp` 适用于成对元素展开，不是通用组件宽度；具体左右位置与内部尺度由组件契约定义。
View 尺寸、density 与目标显示面的像素分辨率分开处理，不能把中心比例当成物理投影角度。
例如离线 View 为 1000×400、cx=.5、cy=.5、sc=.3 时，中心为(500,200)，基础单位为19.2。
这些初始比例与算例不是实车摆放、遮挡范围或可读性的认证。

## 7. 样式与预设：项目约定，需要实现

布局几何、组件样式、字体与预设元数据分层存储，并给各层明确版本。
三套命名预设可用 M1/M2/M3 表示；切换是一个事务，布局、样式与字体一起验证并发布。
预设元数据包含名称、说明及可选的驾驶模式绑定；绑定只选择应用配置，不写车辆驾驶模式。
驾驶模式绑定使用项目枚举与显式稳定策略，读取失败或过期时不凭缓存反复切换。
样式建议以有类型字段对象保存；如需紧凑快照，可用标签 b/i/l/f/s 区分布尔、整数、长整数、浮点、字符串。
这套标签是项目序列化约定，需要实现类型、范围和迁移校验，不作为通用脚本或任意属性通道。

| 样式组 | 项目应定义的参数示例 |
|---|---|
| 公共 | 字体标识、边框、颜色；不把字体选择与通用 sc 混为一项 |
| 媒体 | 封面启用、封面相对倍率、文字／封面显示时限 |
| 轮胎／温度／SOC | 显示子项、阈值启用、阈值与颜色；单位必须跟随数据契约 |
| 电机／踏板／G 值 | 子项、风格、活动显示、字体倍率、线条厚度与颜色 |
| 转向 | 成对间隔与颜色，数据未知时的明确表现 |

字体与图像资产由项目提供；任意字体／图像导入不是首版必需。
完整配置 envelope 只保存六字段组件项；上述样式／预设另用项目定义的版本化文档或存储，不隐式扩展当前 schema。

## 8. 渲染线程、重绘与异常隔离

公共 View／Canvas 的窗口操作与 invalidate 请求回到其所属 UI Looper。
数据读取、网络封面加载、数据库搜索与较重资源解码在工作线程完成，不在 onDraw 中轮询车辆。
渲染使用同一版本的不可变 LayoutSnapshot 与数据快照；不要只复制列表却继续共享可变配置对象。
重绘优先由布局／数据变化触发；时钟按需要更新时间，静态内容不使用忙循环。
动画采用受控 ticker 或平台动画调度；计划间隔不是硬件刷新率或呈现完成保证。
背景或不可见时停掉不必要的 ticker，detach 时移除监听与回调，释放图片及绘制资源。
`en=false` 在本项目中意味着不绘制该组件；告警不得绕过它，除非另有显式、独立的显示策略。
绘制层级由组件注册表明确规定；JSON 数组次序不隐式成为层叠顺序。
每组件绘制异常单独隔离，记录类型、布局版本和错误；一个组件失败不能使全部绘制循环退出。
连续失败的隔离阈值和恢复条件由项目配置定义，UI 给出原因与恢复入口，不无限重启整个服务。
显示面丢失、资源失效、布局切换和停止过程使用代次标记，丢弃迟到的旧任务结果。
运行、窗口附着、提交绘制请求和用户看到内容分别记录，不以服务通知代替物理显示确认。

## 9. 首版离线验收

覆盖完整替换／增量原子性、重复类型拒绝、字段范围与有限性、未知版本拒绝、预设事务及迟到任务隔离。
使用固定 View 尺寸检查比例公式、文字边界、图标占位与多组件异常隔离；测试通过不代表实车可用。
公共平台权限、目标显示面、车辆数据映射和行驶条件下的实际表现另行核验。
