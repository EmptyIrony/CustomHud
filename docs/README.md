# Android 车载 HUD 开发接口包

版本：1.0。日期：2026-11-03。语言：中文。

本包可作为独立 Android HUD 应用的开发输入，覆盖窗口输出、组件布局、渲染、只读数据接入、生命周期、异常处理与验收。它是**非官方兼容性接口草案**，不是厂商 SDK，也不保证任意车型、系统版本、应用身份都能访问 HUD 副屏。

目标应用的 DEVICE 输出、车辆字段和现场生命周期尚未验证；离线可实现的部分与现场待验证的能力分别验收。

## 阅读顺序

1. `implementation-and-acceptance.md`：范围、阶段和交付要求。
2. `platform-interface.md`：Android 平台调用、窗口参数和权限。
3. `lifecycle.md`：应用内会话接口、状态机、资源收尾与恢复。
4. `layout-and-rendering.md`：组件、布局、样式、渲染和预设。
5. `data-interfaces.md`：车辆、媒体、定位与道路提醒数据。
6. `schemas/hud-layout.schema.json`、`examples/layout-full.json`：布局文件约束与示例。
7. `opening-prompt.md`：可直接交给开发助手的开场任务。

## 三类信息

| 分类 | 使用方式 |
|---|---|
| Android 公共接口 | 使用目标 Android 版本支持的 API；仍需检查权限与运行条件 |
| 平台适配候选 | ECARX、车辆属性、显示屏候选等按设备 profile 接入，须单独确认支持、单位与身份 |
| 项目接口约定 | 本包为新应用定义的模型、方法、状态和验收要求，需要开发实现 |

类名或方法签名出现在本包中，不代表已有可直接导入的业务库。应新建独立应用，使用自己的包名、界面、数据模型和资源。

## 能开始到哪一步

可以立即完成项目搭建、离线预览、配置校验、Canvas 渲染、会话状态机、数据模拟、构建和必要测试。实际 HUD 访问、应用授权、车辆字段含义、原厂画面合成及息屏唤醒行为，需要目标设备单独验收。

没有目标设备、厂商库或必要权限时，应交付可构建的模拟实现和清晰的能力状态，不应把缺失能力报告为成功，也不应因此阻塞所有离线开发。

## 运行模式

- `PREVIEW`：普通应用窗口中的本地预览，默认使用模拟数据。
- `DEVICE`：由用户明确进入的现场显示模式，选择已确认的目标副屏。

车辆状态接入只读。现场安装、启动和配置调整由用户确认后手动执行。停止请求必须能结束显示会话；布局错误、数据断连和窗口失败都有明确反馈。

完整性清单见 `manifest.json`。包内不包含应用二进制、厂商库或现成应用工程；所有文档均不依赖特定电脑目录。
